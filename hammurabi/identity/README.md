# Identity studio — concept 01

Open index.html in a browser to browse all 25 character specifications. cast.json contains the full cast; each named JSON file is independently editable. These are original fictional adult identities, not representations of real people.

## Outside: visual and embodied identity

Each profile defines a face, hair, apparent adult age, wardrobe, natural human proportions, posture and gesture states. The generated cast board is saved as cast-board.png and linked from index.html. It is concept artwork, not individual portrait files or a 3D asset. Keep identity versions consistent when producing future portraits, full-body turnarounds, expression sheets and animations. Review generated labels and character consistency before treating artwork as final.

The next production assets for each agent are: a consistent headshot; front/side/back full-body views; neutral/listening/thinking/presenting/uncertain expressions; a rigged 3D or 2D avatar; and lip-sync-ready animation. Those production assets are not yet implemented.

## Voice

Voice direction specifies register, pace and delivery independently of visual presentation. No audio samples have been generated and no text-to-speech provider is connected. Choose a licensed synthetic voice, store its provider voice ID in voice.provider_voice_id, audition a neutral sample, then evaluate intelligibility, latency and pronunciation. Do not clone or imitate real individuals without their authorization. A suggested audition line is: "Hello, I’m [name]. Here is what I found, what remains uncertain, and the next step I recommend."

## Inside: working mind

Role prompts, responsibilities, authority and metrics remain in ../agents/. Identity profiles add a reasoning protocol, memory policy and development loop. They are design specifications; the current runner does not read identity files. Personality, voice and avatar do not improve model competence by themselves. Capability should be evaluated through task success, evidence quality, tool execution and verified outcomes. Human-like appearance does not imply consciousness, personal feelings or actual emotional devotion.

## Integration plan

1. Approve and revise cast designs and voice directions.
2. Produce individual consistent portrait and body assets from approved references.
3. Add an avatar interface that exposes agent name, role, current task and processing state.
4. Connect a licensed speech engine with explicit audio controls and accessible text transcripts.
5. Load approved behavioral identity fields into model prompts; keep appearance out of authority decisions.
6. Evaluate capability independently from charisma or realism. Connect animated states to actual runtime events, rather than inventing activity.
